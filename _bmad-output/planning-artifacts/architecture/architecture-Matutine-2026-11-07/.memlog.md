- (decision) Paradigm is hexagonal ports-and-adapters. Core in shared: models, RSS/Atom parsing, ranking, edition generator, repository port, source ports, AI port. Core knows no client, server, or vendor. Binds all modules. Prevents a second generator or a second edition model in a client or the server.
- (decision) Dependency direction: androidApp, desktopApp, webApp, and server may depend on shared. shared depends on none of them. Clients do not depend on the server module; the remote repository adapter uses HTTP. Binds all modules. Prevents shared importing UI or Ktor, and clients calling server internals.
- (decision) A client process activates exactly one repository implementation, chosen at that client's composition root and invisible to UI. Local generates the edition on device. Remote only fetches the edition and submits edits; it does not generate. Both implementations ship; a configured server selects remote. Binds clients. Prevents UI branching and two generators writing one edition.
- (decision) One edition is one JSON document. The owning store (local store or server) assigns the monotonic revision on each write. Sync is last-write-wins of the whole document: a write replaces the document, with no merge and no conflict rejection. Binds shared, server, and clients. Prevents per-client merge and optimistic-lock 409s.
- (decision) Scheduled generation inserts an edition only when that edition id is absent. A later user edit is a write and therefore wins against the schedule. An explicit regenerate is a full replace. Binds server and clients. Prevents the morning job from wiping same-day edits.
- (decision) Only the shared edition generator assigns rank and the layout model. Clients render that model and do not re-rank. Binds shared and every UI. Prevents Android and Desktop from computing different headline hierarchies.
- (decision) AI is one batched summarization per edition, stored on the edition document, which is the only cache. No key still yields a complete edition via plain headlines or an extractive summary. Keys are injected configuration and are never committed. In remote mode the server config holds the key and clients do not need one. The provider is a port. Binds shared, server, and clients. Prevents a chatbot, a side cache, and a mandatory key.
- (decision) Guaranteed KMP targets are Android and Desktop JVM. No iOS target. The web client is static assets served by the server, uses only the edition HTTP API, does not run the generator, and is not a contest platform. Binds all modules. Prevents an iOS source set and an offline browser stack.
- (decision) Server API is single-user: one shared token, no accounts. A local demo server uses a documented default token. MVP exposure is LAN-only. There is no push channel. Binds server and remote clients. Prevents accounts, Firebase, and public ingress.
- (decision) Remote clients all use one configured base URL. Android network security must allow that URL, including cleartext when the scheme is http. TLS is a configuration of the same URL, not a second API. Binds server and remote clients. Prevents one client requiring HTTPS while another allows only cleartext.
- (decision) Inputs are RSS/Atom, one calendar port, and exactly one task-source adapter. Email is out of scope. The calendar port accepts ICS on every client; Android may also supply the device calendar. The concrete task vendor is not chosen. Binds shared and clients. Prevents email OAuth and two task backends.
- (decision) Clock-precise daily generation exists only in the server coroutine scheduler. Android background fetch is WorkManager and may be approximate. Desktop generates only while its process is open. Binds server, Android, and Desktop. Prevents a shared scheduler that promises a fixed morning time on every target.
- (decision) Platform APIs stay out of shared commonMain: device calendar provider, WorkManager, local notification, widget, tray, local files, PDF, typewriter editor. Shared sees ports and data only. Binds clients and shared. Prevents platform APIs inside the generator.
- (decision) Demo mode must show an edition from bundled sample feeds and sample calendar data, with no account and no AI key. Binds all modules. Prevents a judge path that depends on personal credentials.
- (decision) Distribution of the server includes both a Docker image and a java -jar launch, matching the in-scope packaging line. Which one the README leads with is deferred. Binds server. Prevents one packaging path from being dropped.

- (decision) User: once a server is configured, the current paper is the editions that server generated. With no server, the phone or the desktop owns whatever it generates in its own store. Those local stores are not merged when the server is later configured. Binds clients and server. Prevents a client from still treating its own generate as today's paper in remote mode, and prevents a sync epic from uploading old local editions.
- (decision) User: regenerate replaces the morning edition. A separate action creates an additional edition and leaves the morning edition in place. The morning schedule creates at most one morning edition per generator-day and does not replace it. Only regenerate replaces that body. Each edition stays one JSON document with its own store-assigned id and revision. Binds shared, server, and clients. Prevents a date-keyed singleton and prevents the schedule from using regenerate semantics.
- (decision) User: each client chooses server-synced settings or device-local settings. Settings are a separate JSON document from editions and hold notification time, layout prefs, and other presentation prefs. The mode flag stays on the device. Sync mode reads and writes the one server document last-write-wins. Local mode does not. Switching to sync does not upload the local document. Switching to local copies the server document onto the device and stops writing the server. Binds clients and server. Prevents settings inside the edition and a merge between the two modes.
- (decision) User: show ICS events and Android device-calendar events on every client, once each. The generator is the only place that unions and dedupes. Two events are one when start, end, and title match after trim. Source calendar is metadata, not part of the key. Device events are an input snapshot Android pushes; they are not written into an existing edition. UIs render the edition's event list only. Binds shared, Android, and every UI. Prevents per-screen calendar merges and Android-only events.
- (decision) User: Docker is the required server distribution and the README path. A java -jar launch is later, only after the image works, and must use the same process and config. Binds server. Supersedes the earlier both-required packaging decision. Prevents jar work from blocking the judge path or forking config.
- (decision) Edition and settings JSON on the wire and on disk use kotlinx.serialization and no second codec. Binds shared, server, and Kotlin clients. Prevents a second JSON library from changing the document shape.
- (decision) The shared module's Android target uses com.android.kotlin.multiplatform.library. The Android application plugin lives only in androidApp. Binds shared and androidApp. Prevents the deprecated Android library plugin on the KMP module.
