- (capability) CAP-1 Front page. Intent: the user can open today's paper as one front page, with headline size reflecting importance, a short briefing, today's events, and tasks. Success: Android and Desktop each show that page from sample data, with visibly different headline sizes, and the primary view is not a flat list.
- (capability) CAP-2 With and without a server. Intent: the user can read today's paper on a device alone, and, once a server is configured, on the phone, the desktop, and in the browser as the paper that server generated. Success: with no server base URL the device shows only editions it generated; with one, the front page matches the server's current morning edition and old local editions are not uploaded.
- (capability) CAP-3 Replace or add. Intent: the user can replace the morning paper, or add another edition the same day without replacing the morning one. Success: an automatic later run leaves an edit in place; regenerate replaces the morning edition and keeps its id; a new edition appears in the list and the front page stays the morning edition.
- (capability) CAP-4 Sources. Intent: the user can add RSS or Atom feeds, an ICS calendar, and one task source, and on Android the device calendar is included, with each event shown once on every client of that edition. Success: two events with the same start, end, and title appear once; a phone calendar event shows on desktop and web after the next regenerate or extra edition; email never appears.
- (capability) CAP-5 Edit. Intent: on desktop the user can edit the edition in a typewriter-style editor; in the browser the user can view it and make a light edit; Android does not edit the edition. Success: a desktop change to story or briefing text is what the browser shows for that edition, and rank, events, and tasks are unchanged.
- (capability) CAP-6 Android morning and settings. Intent: the user gets a local morning notification and can keep notification time and layout preferences on the device or follow the server copy. Success: the notification opens the current morning edition; local mode does not write the server settings; turning sync on shows the server settings and does not upload the old local copy.
- (capability) CAP-7 Optional briefing. Intent: the briefing can be an AI summary, and the paper still completes with no key. Success: sample mode produces an edition with no AI key; a generation makes at most one summary call; the summary is stored on that edition; a provider that needs paid credits is not used.
- (capability) CAP-8 Run it for a judge. Intent: a judge can reach a visible edition on Android, Desktop, and the server-hosted page without an account or a paid key. Success: the README's steps go from clone to that edition on Android and Desktop in a few minutes, and the Docker image serves the same morning paper on the LAN.
- (capability) CAP-9 Desktop presence. Intent: while the desktop app is open, the user can reach it from the system tray and open a local file. Success: the tray icon is visible, and a file the user chooses can be read.
